## Tags
     A tag must exist as an entity before it can be assigned to anything. Create it with createTag, then attach it with addBlockTag.
    Assigning a tag to a page and to a block are the same operation — a page is a block in the DB, so both take the target's UUID. Resolve the UUID before attempting any tag change.
    Tags are identified by their UUID for relation operations. addBlockTag and removeBlockTag take two UUIDs: the target first, the tag second.
    Tags also carry a :db/ident (:user.class/xzy-bc0auNqC), used for lookups rather than relations. Unlike plugin property idents, tag idents get a random suffix, so they can't be constructed from the name and must be read back after creation.
    Removing a tag from a target removes only that one relation; the target's other tags and the tag entity itself are unaffected.
    Tags declare property slots via :logseq.property.class/properties. A page tagged with a class inherits that class's properties as available — declared, but unset until a value is assigned.

    Tag removal has no upsertNodes route. operation offers only add and edit, so retraction must go through removeBlockTag.
    Tags land in user.class/* and appear not to be subject to the sandbox that blocks user.property/* writes

## Property
    A property must exist as an entity before it can be assigned to anything. Create it with upsertProperty, then assign values with upsertBlockProperty.
    Assigning a property to a page and to a block are the same operation — a page is a block in the DB, so both take the target's UUID. Resolve the UUID before attempting any property change.
    Properties are identified by their :db/ident (:plugin.property._test_plugin/Effort), not by title or UUID. Deletion via removeProperty keys on the ident.
    Some properties are built in, such as Status, Priority, Deadline, Scheduled, and Alias. These live in the :logseq.property/ namespace and are declared by classes rather than created by you.
    Every property has a type: default (text), number, string, datetime, checkbox, url, node, page, class, property, or map. The type determines what a valid value looks like — reference types take an entity, not a literal.
    Properties also carry a cardinality (one or many), which determines whether assigning a value replaces the existing one or adds to a set.
    
    Property writes over HTTP are sandboxed to plugin.property.<your-plugin-id>/*. Properties created in the UI land in user.property/* and can't be written or removed through the API.
    Plugin-namespace idents are deterministic — :plugin.property._test_plugin/<Title> with no random suffix — so you can construct them client-side rather than reading them back. User-namespace idents do get random suffixes and must be looked up.

	- changing a title of a a block require you to use the BLOCK-UUID
	
    - ### Basic Commands
		- getBlockUUID($PAGE-UUID)
			- {"method": "logseq.DB.datascriptQuery", "args": ["[:find (pull ?b [:db/id :block/uuid :block/title :block/order {:block/parent [:block/uuid :block/title]}]) :where [?p :block/uuid #uuid "$PAGE-UUID"] [?b :block/page ?p]]"]}
		
        - createBlock(PAGE-UUID, $title):
			- {"method": "logseq.DB.upsertNodes", "args": [[{"operation": "add", "entityType": "block", "data": {"page-id": "$PAGE-UUID", "title": "$title"}}]]}

        - removeBlock($BLOCK-UUID)
