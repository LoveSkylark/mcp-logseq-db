# MCP Tool Improvement Plan

Ordered so each instruction is independently shippable. Phase 1 is cheap and safe; Phase 2 is where the real cost savings are; Phase 3 needs upstream verification first. Two pairs are marked where splitting them makes no sense.

Every item traces to something that actually cost us in this session, noted under *Evidence*.




---

### Instruction 12 — `splitBlock(uuid, offset | delimiter)`

**Why:** `updateBlock` is title-only, so there's no inverse of a merge.

**Addresses:** the Feb 28th mechanics summary has headings fused onto the tail of the preceding paragraph — `"…both dice succeed [1]\n\n**Modifiers:**"`. "Modifiers:", "Equipment:" and "Special Effects Die:" are all trapped mid-block and can't be promoted to their own headings.

**Works with:** cleaning up any pasted or generated content, which is a large share of this graph.

**Implementation:** `updateBlock` the original to the first part, `createBlock` the remainder, `moveBlock` it to `after`. Composition of existing primitives.

**Concerns:** not atomic — a failure between steps leaves truncated text, which is data loss in the user's prose. Do the create before the truncate so the content exists twice at the worst moment, never zero times.

**Done when:** a two-part block splits into two correctly ordered blocks with no text lost.

### Instruction 13 — `migratePage(source_page, target_page, filter?)`

**Why:** journal-to-page migration was the whole job and has no primitive.

**Addresses:** the complete workflow — enumerate top-level blocks, move them in order, verify, report what's left.

**Works with:** the remaining Feb 10th and Feb 11th chapters; any future journal cleanup.

**Implementation:** build on Instruction 7. Do this last — it's a convenience wrapper, and it's only worth writing once the batch move underneath it is solid.

**Concerns:** don't let it decide *what* to migrate. Placement judgement — which cluster belongs on which page — was the irreducibly human part of this session, and the one the tool shouldn't touch. Keep it mechanical: "move these blocks there", not "work out where this belongs".

## Cross-cutting concerns

**Document the two behaviours we found the hard way.** Recycled pages can be renamed and this releases the title; `getPageUUID` and the write path disagree on recycled titles. Both contradict the current reference files, and both caused mistakes today. Also correct write-workflows' stale "There is **no move**. No route exists for it" and data-modeling's "No block movement — yet."

**Keep verification, cut the echo.** The read-back-and-compare discipline is the best thing about this toolset and caught real failures. Instruction 2 targets the response size, not the checking.

**Prefer additive changes.** Every item here is a new tool, a new enum value, or a new optional parameter. Nothing redefines existing behaviour, so nothing needs a coordinated client update.

**Sequencing:** 1 → 2 → 7 unlocks the most, in that order. Instruction 1 is a prerequisite for 7; 7 is a prerequisite for 13. Everything else is independent.
